# 호스트 보안 업데이트 점검

`tools/audit_host.py`는 운영체제 식별값, 실행 중 커널의 버전·아키텍처, 명시한 PHP CLI 바이너리의 버전, DNF 보안 권고 메타데이터를 비공개 JSON으로 모읍니다. 패키지를 설치하거나 서비스를 재시작하지 않으며, 방화벽·네트워크 설정·스케줄러를 만들거나 바꾸지 않습니다.

```bash
python3 tools/audit_host.py \
  --php /absolute/path/to/trusted/php \
  --php /another/explicit/php \
  --output /private/operator-directory/host-audit.json
```

`--php`는 필요할 만큼 반복합니다. 자동으로 프로세스를 탐색하거나 PHP 경로를 추측하지 않습니다. 신뢰할 수 있는 CLI 실행 파일만 지정하십시오. PHP에는 `-n`과 고정된 버전 조회 코드만 전달하므로 호스트 php.ini·prepend 파일·애플리케이션 코드를 로드하지 않습니다. 별도 작업용 PHP wrapper를 지정하면 wrapper가 자체적으로 구성하는 확장이 있을 수 있으므로 신뢰 경로를 먼저 확인해야 합니다. 어떤 바이너리도 지정하지 않으면 PHP 검사를 `unknown`으로 기록합니다.

PHP 버전 판정은 phese CLI와 같은 최소 수정 버전 표를 사용합니다. 대상은 CVE-2026-109618 및 CVE-2026-109619이며 PHP 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12부터 해당 브랜치의 upstream 버전 기준을 충족합니다. 이전 버전은 업데이트 또는 정확한 배포판 backport 증거 검토 대상으로 기록합니다. 숫자만으로 backport 적용 여부나 실제 공격 가능성을 확정하지 않습니다. 새로운 브랜치·시험판·조회 실패는 `unknown`입니다. 이 점검은 phese 확장 로드 상태나 실행 중 worker의 PHP 버전을 확인하지 않습니다.

DNF는 고정된 시스템 경로에서 찾고 먼저 `dnf updateinfo --help`로 필요한 옵션의 지원을 확인한 뒤 다음 조회만 실행합니다. 도움말은 최대 10초, 목록 조회는 최대 45초입니다.

```bash
dnf -q updateinfo list --security --available --with-cve
```

`--with-cve` 때문에 CVE 참조가 있는 보안 권고가 대상입니다. DNF는 기존 저장소 인증 설정을 자체적으로 이용할 수 있고 메타데이터를 조회·캐시 갱신할 수 있습니다. 도구는 저장소 설정이나 인증 파일을 직접 읽지 않고, 저장소를 추가하거나 변경하지 않으며 패키지를 다운로드·설치하지 않습니다. DNF가 없거나 필요한 옵션을 지원하지 않는 배포판에서는 패키지 점검을 `unknown`으로 남깁니다.

명령 실패·타임아웃·표준 오류 경고·완전히 해석하지 못한 목록은 `unknown`입니다. 원본 오류와 출력은 인증 정보가 포함될 수 있으므로 저장하거나 콘솔에 출력하지 않습니다. 인식한 CVE·권고·패키지 식별자와 검토 권고만 비공개 보고서에 기록합니다. 목록에 항목이 없다는 사실도 저장소 메타데이터 범위의 조회 결과일 뿐, 모든 취약점이 없거나 보호된 상태라는 판정이 아닙니다. 보고서는 항상 `all_cves_protected: false`를 포함합니다.

보고서는 `phese.cli.private_json`으로 원자적으로 쓰며 권한은 `0600`입니다. 출력 디렉터리는 실행 사용자 소유이며 다른 사용자가 쓸 수 없어야 하고, 출력 파일 심볼릭 링크는 거부합니다. 콘솔에는 숫자별 집계, `unknown` 개수와 보고서 경로만 나옵니다. 비공개 보고서를 공개 저장소에 커밋하지 마십시오.

종료 코드 `0`은 선택한 검사가 완료되고 검토 대상으로 집계된 항목이 없음을, `1`은 업데이트·검토 항목이 있음을, `2`는 `unknown`이나 보고서 쓰기 실패가 있음을 뜻합니다. 어떤 종료 코드도 모든 CVE의 차단을 의미하지 않습니다.

호스트 패키지 메타데이터는 수동 빌드한 PHP·웹서버·라이브러리, 컨테이너 이미지, 애플리케이션 의존성을 모두 포함하지 않습니다. 커널 식별값 조회 자체도 커널 보안 판정이 아닙니다. 보고서의 항목을 바탕으로 별도 호환성 검증과 업데이트 계획을 만들고, 실제 배포 뒤 실행 중 바이너리까지 다시 확인해야 합니다. 이 도구는 소스·환경변수·프로세스 명령행·인증 파일을 조사하지 않습니다.

검증은 실제 DNF·PHP를 실행하지 않는 명령 대역과 비공개 파일 fixture로 수행합니다.

```bash
python3 -m unittest discover -s tests -p 'test_audit_host.py' -v
```
